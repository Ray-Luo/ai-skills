# 理论、数学、算法证明专项审查（Theory & Proof）

仅当论文的核心承诺是定理、界、收敛性、可识别性、算法正确性或理论机制时加载。**核心证据单元可以是 Definition / Lemma / Theorem / Proof / Counterexample，不必有图。**

## 先确定论证目标

- 用精确量词重述主定理：对什么对象、在什么假设下、保证什么结论？区分必要条件与充分条件、最坏情形与平均情形、渐近与有限样本结论。
- 标出符号、定义域、概率空间、独立性、光滑性、可实现性、oracle 或计算模型；检查假设是否彼此一致及是否隐含难以满足的条件。
- 查清定理与直觉性说法之间的差别：存在性不等于可构造性；收敛不等于实际速度快；上界不等于下界或最优性。

## 证明审查链

1. **Proof dependency graph**：主定理 ← 引理 ← 被引用的前作或假设，注明每一步来源；缺少的证明标 `[U]`。
2. **关键跳步**：不等式方向、极限交换、对偶性、概率界、对数/指数换算、隐含常数、边界情况；未亲自验证不写“证明无误”。
3. **最小反例**：零维/一维、退化矩阵、极端分布、相等边界和违背某一假设的情形，区分「定理本身错」与「适用前提不满足」。
4. **对照选择**：是否比较了同问题定义、相同 oracle/信息/资源模型下已有的紧界和理论？换一种证明技巧不必然带来更强结果。
5. **实验的地位**：数值模拟可检验直觉或展示行为，但不能代替一般性定理证明；若论文宣称可用性，需要独立的实验有效性证据。

## 六问与研究卡的适配

- 对证据单元（例如 Theorem 2 + Proof）仍用「为什么做、怎么做、怎么看、发现什么、支持到哪、为何转到下一证据单元」；第三问改为**如何检查定义、量词和关键推导**。
- Research Card 可写成「猜想 → 条件 → 证明思路/反例搜寻 → 对照定理 → 判定标准/放弃条件」，不强迫填写数据集、GPU、p-value。无法证明 ≠ 定理为假；停止条件应写明搜索边界和转向规则。

## 常见过度外推

- 理论前提只在理想化分布成立，却推断所有真实数据集必然有效。
- 渐近复杂度降低就宣称小规模运行更快，忽略隐藏常数与实现成本。
- 证明了某个代理目标最优，叙述成整个真实应用目标最优。
