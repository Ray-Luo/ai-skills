# 研究类型与证据主张路由（Research-Type Router）

**不要把这份表当通用打分表。** 先问「论文承诺证明什么」，再选最能检验该承诺的证据。一个论文可属于多个类型；默认选**主类型 + 最多两个真正相关的专项模块**，避免一次性读完全部 reference。

## 一、先判断论文类型

| 主要类型 | 何时选用 | 加载参考文件 | 优先审查 |
|---|---|---|---|
| 实证 ML / CV / NLP | 用数据证明模型或方法更好 | 当前清单的「ML 核心检查」；若涉及 SR / NVS 追加 [`vision-restoration-sr.md`](vision-restoration-sr.md) | baseline、消融、训练/测试协议、泛化 |
| 理论 / 数学 / 算法正确性 | 提出定理、界、证明、算法保证 | [`theory-and-proof.md`](theory-and-proof.md) | 定义、量词、假设、证明义务、反例 |
| 系统 / 工程 / 性能 | 提出加速、吞吐、可靠性或成本优势 | [`systems-and-benchmarking.md`](systems-and-benchmarking.md) | 工作负载、测量边界、matched-quality、波动 |
| 数据集 / Benchmark | 发布新数据或评测协议 | 当前清单的「数据集核心检查」 | 代表性、标签质量、泄漏、协议诱导偏差 |
| 因果 / 观察性实证 | 宣称处理/政策/暴露导致结果变化 | [`causal-inference.md`](causal-inference.md) | estimand、识别假设、混杂与选择偏差 |
| 临床 / 生物医学 | RCT、诊断、预后、队列、动物/体外实验 | [`clinical-and-biomedical.md`](clinical-and-biomedical.md)，观察性因果主张再加因果模块 | 效果、伤害、偏倚、适用人群、伦理 |
| 定性 / 混合方法 | 访谈、民族志、田野与主题分析 | [`qualitative-research.md`](qualitative-research.md) | 抽样、反身性、材料→解释的链条、负例 |
| Survey / Review / Meta / Position | 对文献进行归纳、综合或立场论证 | [`evidence-synthesis.md`](evidence-synthesis.md) | 检索覆盖、可比性、偏倚、论据与反例 |

**混合方法示例**：含临床试验与访谈的论文，同时审查临床实验的因果与伦理边界、定性资料的解释链，但不要给整篇论文套一个总分。结合 ML 与系统的论文，同时审查输出质量与端到端速度；声称因果的观察性 ML 研究，要再加载因果模块。

## 二、再判断主张类型（Claim-Type Lens）

同类型论文可能做不同承诺；基于核心主张补充对应问题：

| 主张 | 至少需要什么证据 | 不能自动推断 |
|---|---|---|
| **性能优于比较对象** | 相同任务/设置下匹配预算、强基线、误差/方差、适用条件 | 在所有条件上最好 |
| **组件/机制导致提升** | 能区分备选机制的消融、干预或理论推理 | ablation 显示差异就证明唯一机制 |
| **X 因果影响 Y** | 可信的因果识别假设及对应诊断 | 相关性、控制变量、显著性即因果 |
| **定理/算法保证** | 精确定理、可核对的证明义务与前提 | 假设外的真实部署也有保证 |
| **可推广/鲁棒** | 不同分布/人群/设备的独立证据 | 单一 benchmark 可以代表全部应用 |
| **安全/有效/适合应用** | 目标应用的效益、伤害、失败模式与部署条件 | 未报告失败即不存在失败 |
| **综合共识/证据充分** | 检索覆盖、研究可比性、偏倚与分歧处理 | 多篇同方向论文即可下普遍结论 |

## 三、通用审查底线

- `[P]` 只表示原文报告，`[A]` 表示作者解释，`[R]` 是审读者推断，`[U]` 是缺失/无法核对；明确原文位置与阅读覆盖。
- **报告规范（reporting guidelines）主要评估报告是否透明**，不能作为偏倚风险、证据强度或研究价值的万能评分量表。
- `standard/deep`：逐图/表审查可读证据；若论文主要依赖定理、案例、引语、档案或论证段落，则采用**对应证据单元**开展六问，且说明没有图表或图表不可读。
- 多种主张分别判定：同一论文可以「性能部分支持」「机制证据不足」「范围外推无法核实」，不得整体贴上单一好/坏标签。

### ML 核心检查（如适用）

- 数据拆分、去重、预训练与 benchmark 重叠、评估协议、训练/搜索预算、公平复现的 baseline。
- 消融是否隔离变量（backbone/参数/计算公平）、多种 seeds/方差、多个任务/外部分布及失败样例。
- 指标是否匹配主张；统计显著 ≠ 实用重要；强指标 ≠ 没有幻觉/安全风险。
- 代码、权重、超参、硬件、许可证以及训练/推理资源是否支持复现。

### 数据集 / Benchmark 核心检查（如适用）

- 目标总体、采集途径、许可/隐私、筛选、类别覆盖、标签定义、标注者一致性与系统偏倚。
- 按主体/场景/时间拆分是否防止泄漏、近重复、标注泄漏和评测污染？
- 新 benchmark 的指标能否代表所宣称真实任务？是否需要跨数据集、外部验证或人工评价？
- 设计选择（样本权重、类别频率、评估阈值）改变是否重排方法排名？

## 判定词与操作含义

- **支持**：直接证据支持限定条件下的主张，未识别足以推翻该限定主张的关键缺陷。
- **部分支持**：只覆盖部分人群/范围/尺度，或仅有间接机制证据。
- **证据不足**：缺少能够辨别主要竞争解释的关键证据。
- **与证据冲突**：数据/证明/方法与主张必要条件矛盾。
- **无法核实**：来源、图表、补充资料、证明或数据当前未能访问。

所有判定附上最小可改变判断的新增证据；**不以打分取代研究判断**。
